# ניסוי למידה וירטואלי

הניסוי משווה שלוש שיטות באופן מקומי בדפדפן. הוא אינו קונה או שולח טפסים, אינו מעביר שורות לטופס המשחק ואינו מקבע PIN. ארבעת טופסי ה־PIN הקיימים, מספריהם והיסטוריית הזכיות שלהם נשארים נפרדים, וכך גם מטמון ה־Backtest.

## התחלה ושימוש שוטף

פתחו את „ניסוי למידה” באזור הניתוח וטענו את קובץ ברירת המחדל של האתר באמצעות כפתור טעינת הנתונים. התחלה חיה דורשת לפחות 700 הגרלות מודרניות רצופות ותקינות. מקור ידני, אפילו קובץ בשם `NUMBERS.xlsx` עם אותם בתים, אינו רשאי להתחיל או לקדם מעקב חי.

לחצו „התחל ניסוי ושמור טופס”. החישוב נעשה ב־Worker ויכול להימשך זמן. רק הודעת השמירה והטופס השמור מעידים שהפעולה הצליחה. „בטל חישוב” מבטל עבודה שטרם נשמרה. התהליך אינו ממשיך ברקע כשהאתר סגור.

לכל יעד חדש נוצרות 14 שורות חדשות לכל אחת משלוש הזרועות. אין המתנה של 20 הגרלות כדי לייצר טופס: כל 20 יעדים נבחנת מחדש רק בחירת חלון השיטה הלומדת. הבחירה היא בין חלונות של 100, 200 ו־500 הגרלות, לפי 200 יעדים קודמים. מספרים שכבר נשמרו, ה־seed וחותמת הזמן שלהם אינם משוכתבים בעקבות תוצאות חדשות.

שלוש הזרועות הן:

- השיטה הלומדת, בחלון שנבחר לפי הפרוטוקול.
- „שיטה קיימת + השלמה קבועה”: מחולל הבסיס על 500 ההגרלות הקודמות. שורה תקינה של שישה מספרים נשמרת כפי שהיא. שורה קצרה תקינה מושלמת לפי שכיחות באותו עבר בלבד, בסדר מספרי עולה בשוויון. אין שינוי בטופסי ה־PIN או במחולל הרגיל מחוץ לניסוי.
- ביקורת אקראית עם seed קבוע לניסוי, לשחזור ההשוואה.

„השהה יצירת טפסים” עוצר יצירה חדשה. טעינת מקור האתר יכולה עדיין להתאים תוצאות לטפסים שכבר נשמרו. „המשך ניסוי” מפעיל מחדש, ואם מקור אתר תקין כבר טעון, מכין את היעד הנוכחי. הפעולה אינה מביאה מעצמה קובץ תוצאות חדש מהאתר.

## רענון, החמצות וזמן

החישוב משתמש בנתונים שנטענו. כדי לקבל הגרלות חדשות יש לטעון שוב את קובץ ברירת המחדל. פתיחה מחדש משחזרת את המעקב השמור, אך אינה שקולה לטעינת מקור תוצאות עדכני. אין כאן טיימר שמביא תוצאות אוטומטית ואין עיבוד כשהאתר סגור. שינוי טווח השורות בניתוח הרגיל אינו משנה את המקור המלא של הניסוי.

אם חלפו כמה הגרלות ללא טופס שמור, הן מסומנות כחסרות. אין יצירת טפסים בדיעבד עבורן. אפשר להכין רק את היעד הבא אחרי ההגרלה העדכנית במקור התקין.

תאריך ההגרלה לבדו אינו מעיד על שעתה. כשאין שעה רשמית, רק טופס שנשמר לפני תחילת יום ההגרלה באזור `Asia/Jerusalem` זכאי לראיות עתידיות. טופס מאותו יום או מאוחר יותר מוצג בנפרד ואינו נחשב הוכחה לביצוע מוקדם. השעון והמידע מקומיים ואינם אישור חיצוני בלתי תלוי.

אפשר לפתוח שתי לשוניות באותו דפדפן ואותו מקור אתר. האחסון מונע שכפול יעד או החלפת seed, אך אינו מסנכרן תצוגה ברציפות בכל הלשוניות. במקרה של תצוגה ישנה או התנגשות, טענו מחדש ובדקו את המצב השמור לפני ניסיון נוסף.

## בדיקה היסטורית ופירוש התוצאות

בלשונית „סימולציה היסטורית”, „בדיקה היסטורית” דורשת לפחות 900 הגרלות מודרניות רצופות. אפשר להשתמש גם בקובץ ידני תקין. היא בודקת 200 יעדים אחרונים עם seed קפוא `learning-history-v1`, תוך שימוש רק בעבר שקדם לכל יעד. היא אינה מוסיפה טפסים או תוצאות למעקב החי ואינה משנה PIN או Backtest.

המדד הראשי הוא בינארי לכל יעד: האם לפחות שורה אחת מתוך 14 השיגה שלושה מספרים רגילים או יותר. מספר חזק, סכומי זכייה, מספר השורות הזוכות ומדדי 4+/5+/6 אינם משפיעים על בחירת השיטה. הם מוצגים כתיאור נוסף בלבד.

הערכת היתרון שמרנית ונעשית בבלוקים קבועים ולא חופפים של 200 מיקומי יעד, המעוגנים בתחילת הניסוי, מול שתי הביקורות ובתיקון לבדיקות חוזרות. יעד חסר או מוחרג נשאר במיקומו: לא ממלאים את מקומו בתוצאה מאוחרת יותר. בלוק לא שלם או עם מיקומים חסרים/מוחרגים הוא תיאורי בלבד. מספר הבלוק `k` מתקדם עם מיקומי היעד ואינו מתאפס גם אחרי בלוק שאינו כשיר לראיות. עבור בלוק מספר `k`, תקציב הטעות לכל השוואה הוא `0.05 / (2*k*(k+1))`; הגבול התחתון להפרש הבינארי הוא `mean(D) - sqrt(2*ln(1/alpha)/200)`, ונקטם ל־‎-1. כותרת של יתרון דורשת בלוק מלא וכשיר ותמיכה מול שתי הביקורות. נתונים חסרים, מדגם לא מספיק, בדיקה היסטורית או גיבוי מיובא אינם ראיות עתידיות מאומתות.

זכיות הן סכומים היפותטיים של לוטו רגיל לפני מס, לא אישור שהטופס נשלח או שכסף שולם. „רענן נתוני זכייה” מעדכן נתוני פרסים זמינים לטפסים השמורים בלי להחליף את מספריהם. סיכום חלקי מציין במפורש כמה יעדים חסרים; חוסר מידע אינו אפס זכייה. אין כאן חישוב תשלום, הוצאה, תשואה או רווח נקי. אין הבטחה לשיפור סיכויים, לרווח או לחיזוי הגרלות.

## שמירה, גיבוי ותקלות

הניסוי נשמר ב־IndexedDB בשם `lottoLearningExperimentV1`, בנפרד ממפתחות PIN ו־Backtest ב־localStorage. הוא שייך לדפדפן, לפרופיל ולמקור האתר. אין חשבון, שרת אחסון או סנכרון בין מכשירים. מחיקת נתוני האתר עלולה למחוק אותו וגם נתונים אחרים.

„ייצא גיבוי” מוריד JSON של המצב המוצג. „פתח גיבוי לקריאה בלבד” מציג גיבוי בלי לשחזר אותו לאחסון הפעיל ובלי להתיר המשך מעקב ממנו. הוא מסומן לא מאומת. „חזרה למעקב המקומי” מחזירה לתצוגת הניסוי המקומי. שמרו את הקובץ במקום בטוח. פורמט לא נתמך נדחה או מוצג לקריאה בלבד; מידע שלא ניתן לייצא בבטחה מציג שגיאה ולא מוחלף בשקט.

- אחסון מלא (`STORAGE_QUOTA`) או לא זמין: הטופס החדש לא נשמר. ייצאו את המצב הקיים אם אפשר, בדקו הרשאות/שטח פנוי, וטענו שוב. אל תמחקו נתוני PIN או את כל נתוני האתר כפתרון אוטומטי.
- גרסה לא תואמת, `INCOMPATIBLE_STORE` או `STORAGE_CLOSED`: הפסיקו ניסיונות כתיבה, שמרו גיבוי אם אפשר, סגרו לשוניות ישנות ופתחו גרסה תואמת. אין שדרוג כפוי או מחיקה אוטומטית של המידע הישן.
- `REVISION_CONFLICT`: לשונית אחרת התקדמה. טענו מחדש את המצב ובדקו את היעד השמור לפני המשך. אין להתחיל ניסוי חדש רק כדי לעקוף התנגשות.
- התנגשות נתונים או `EXPERIMENT_CONFLICT`: עבר שכבר שימש בניסוי השתנה. הניסוי נעצר כדי לא לכתוב היסטוריה מחדש. ייצאו גיבוי ובדקו את מקור התוצאות וההודעה הטכנית; אל תשנו טפסים ישנים ואל תנקו את נתוני PIN.
- מקור חסר/לא תקין או Worker לא זמין: בדקו את הדפדפן ואת טעינת קובץ האתר. טעינה ידנית אינה מעניקה הרשאת מעקב חי. פעולות הניתוח וה־PIN הישנות נפרדות מהניסוי.

## Developer test prerequisites

No dependency installation or committed browser vendor bundle is needed. Provide a Node runtime with Playwright, an installed Chromium/Chrome, and Python with `openpyxl`. Set:

```powershell
$env:NODE_PATH = '<existing Node packages directory>'
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH = '<installed Chrome or Chromium executable>'
$env:LOTTO_LEARNING_PYTHON = '<Python executable with openpyxl>'
$env:LOTTO_LEARNING_SHEETJS_PATH = '<cached xlsx.full.min.js for SheetJS 0.20.3>'
```

The SheetJS file is the application's pinned asset at `https://cdn.sheetjs.com/xlsx-0.20.3/package/dist/xlsx.full.min.js`. Prepare it once in an OS temporary cache if absent, record its SHA256, and reuse it. If unavailable, report ingestion verification blocked rather than substituting a parser stub. The tested cache SHA256 was `CC015130AA8521E7F088F88898EBA949CCDCBFB38DF0BD129B44B7273C3A6F41`; this records tested bytes, not independent authentication. Tests route the CDN request locally and do not download it themselves.

Run `node tests/verify-learning-regression-playwright.js` for the independent openpyxl-to-real-SheetJS regression. Genuine generation/replay has targeted long waits. The helper reads fixture JSON on stdin and emits XLSX bytes on stdout without writing workbooks to the repository. Existing UI/controller tests share the same actionable SheetJS preflight.

For the full gate, enumerate **all** `tests/*.js`, retain each exit code even when another test fails, then run `python -m unittest discover -s tests -p 'test_*.py' -v` and `git diff --check`. Report every nonzero suite. Windows scheduler recovery permissions/locking failures are separate from this feature and must not be concealed as a fully green project run.
